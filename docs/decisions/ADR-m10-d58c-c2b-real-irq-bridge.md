## Decision and proof boundary

Prove separately flagged real x86 IRQ0 M10-A priority handoff while the low-priority owner holds an actual rank-0 D5.3 mutex and a high-priority waiter is truly BLOCKED on its original cooperative RET saved stack. Four independent physically mapped 16-KiB M2 stacks are required: low owner (initial cooperative entry; when IRQ0 first interrupts it, real 20-qword hardware source), high waiter (COOPERATIVE_RET only), medium CPU worker (independently built verified initial IRQ IRETQ context), reserved supervisor slot15 (separate verified initial IRQ IRETQ context). Boot dispatcher is a permanent fifth, separately owned surviving stack, not a competing M10-A task.

Boot with selector **disarmed**. Owner acquires rank 0 on own RUNNING stack, temporarily BLOCKS awaiting external event and switches off-stack at IF=0; high acquires with real D5.3 BLOCKED result and switches off at IF=0, preserving its RET continuation. Create READY medium/supervisor with genuine independently owned IRETQ startup frames, wake owner externally, dispatch owner via exact M10-A selected operation. Only when owner is on its verified stack and has a real high BLOCKED donor, arm the new IRQ0 selector under IF=0. Genuine IRQ0 must validate source hardware frame and target saved frame with D5.8c whole graph and D5.8b/D5.8c-C2b exact-generation context-form gate, then use only kernel_task_irq_handoff to transfer the M10-A RUNNING identity; no D5.3 mutation, frame fabrication, EOI, allocation or reaper in IRQ. The reserved supervisor uses a separate verified exact-generation frame (never D5.3 ordinary lock graph) and records actual completed CPU work. D5.7 read-only priority chooser must select the donated owner over medium when owner is READY, and source/target interrupt frames must remain complete.

After >=12 authentic IRQ slices of both low and medium, >=12 supervisor slices, and bounded supervisor service gap, the RUNNING owner must disarm the IRQ selector with IF=0 before it calls D5.3 release. The release transfers ownership/wakes high; at that point high becomes READY but remains RET-form, and must NEVER enter an IRETQ selector. Owner physically switches off-stack to permanent boot via its original cooperative context, retaining IF=0 until the switch completes. The supervisor then terminates the READY medium/supervisor IRETQ-only tasks without interpreting their saved frames as RET contexts, dispatches/resumes high via its saved exact cooperative context, observes genuine lock release/exit, resumes owner through its cooperative context to finish, and reaps physical stacks only when all execution is off them and D5.2b has no registered refs.

## Safety and acceptance

Reject stale owner/waiter generations, invalid frames/segments/stack bounds, malformed graph, orphan, active critical section, wrong context form or missing supervisor readiness BEFORE M10-A IRQ handoff; never release a lock or free a referenced stack as a recovery shortcut. On an indeterminate fault, disarm selector if possible, stop diagnostic on the current verified stack, and do not claim normal editor boot. All data structures fixed size and single boot CPU. QEMU 128,256,512MiB under -net none without any physical disk; exact serial metrics must show real owner/medium handoffs while high BLOCKED, donated medium-to-owner selections, completed bounded supervisor service, real wake + cooperative high continuation, off-stack owner/reaper and editor. Negative fixtures should run under separate flags and fail closed without unsafe target IRETQ. Full inherited D2–C2a and hosted C2b tests plus exact-head CI, unchanged normal stripped kernel and D4 accepted ISO required before accepting this physical phase.

Tradeoffs: four independently backed contexts and explicit disarm/off-ramp are more complex than pretending RET and IRETQ are interchangeable; they avoid fake saved frames. No production-wide IRQ locks/allocators/editor audit, FPU/SIMD, Ring3/CR3, SMP, hard real-time hardware guarantees or owner-death recovery; even passing this diagnostic is not permission to enable normal program preemption.
