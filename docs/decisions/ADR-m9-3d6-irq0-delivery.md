# ADR M9-3D6 — Controlled boot-CPU APIC IRQ0 and monotonic PIT timer

Status: owner authorized implementation, review, merge and QEMU-only deployment after tests on 2026-11-12. This ADR governs the smallest end-to-end IRQ0 checkpoint; no physical media or broader interrupt ABI is approved.

## Prior evidence and context
The M9-3 legacy-PIC-only IRQ0 experiment (draft #40, Issue #41) did not deliver any ticks on QEMU q35 because the LAPIC's LINT0 ExtINT route was masked and IOAPIC redirections were masked. The approved APIC-first discovery/preflight and private mapping stack (PRs #42–#47) culminated in M9-3D5 (#49/#50), verified ACPI/MADT and xAPIC IDs, PAT/MTRR and absent known HHDM aliases, IOAPIC version/pin span and IRQ0 GSI, and successful host/QEMU regression. It intentionally kept IF=0 and no hardware routing. M9-3C provides the 100 Hz monotonic software tick, unavailable until first real IRQ.

## Choice and safety gates
One boot CPU in xAPIC mode; use *only* M9-3D5 validated private LAPIC/IOAPIC virtual MMIO windows. Refuse unsupported SMP, mismatched IDs, invalid GSI capacity, unsupported override flags or cache/alias uncertainty. Require IF=0 through device programming; PIC remains fully masked. Reserve vector **0x30** for hardware PIT0; install one interrupt gate and a spurious LAPIC vector **0xFF**, without changing CPU exceptions 0..31 or PIC vectors 32..47. The IRQ0 assembly entry preserves all interrupted general-purpose registers, aligns the C call stack, invokes only a bounded tick + LAPIC EOI and returns via IRETQ. No heap, serial, blocking work, scheduler, or physical timer calibration in interrupt context.

Snapshot and validate controller register states before changing anything. Never unmask or rewrite unrelated IOAPIC pins. Require all unrelated pins already masked or mask them through an independently tested bounded transaction; fail closed if another device is live. Set only the verified IRQ0 source GSI to fixed delivery, physical destination = validated boot APIC ID, vector 0x30, expected edge/high ISA timer polarity/trigger. Preserve all other interrupt sources masked; never treat unknown ISO flags as supported. Enable local APIC software routing using a known valid spurious vector gate; require SVR read-back and mask LINT0 legacy ExtINT as necessary without disrupting LINT1 NMI. Program PIT **channel 0 only** with mode 2 and reload 11932 using 1,193,182-Hz input for nominal ~100 Hz. PIT channel 2 and PS/2 keyboard and COM1 polling remain unchanged.

Enable IF only after the IDT gates, valid M9-3D5 platform, fully validated register read-back, one IOAPIC IRQ0 route, all others masked, usable LAPIC EOI and software timer init. If setup fails before IF, return safely to the normal polled diagnostic editor without claiming a timer; masks must be restored or fail fatally with IF=0 if rollback cannot be proved. After IF=1, avoid trying to remove IRQ0 routing without CLI and controlled teardown. Loss of ticks or storms must never silently claim elapsed wall-clock time. Boot can report timer readiness after first real IRQ, with timestamp bounds in test image only; normal loop stays responsive.

## Reject and defer
Do not use legacy PIC virtual-wire workaround; fixed QEMU physical APIC addresses; an unverified direct-map alias; user-facing IRQ ABI; driver/scheduler/preemption/PS2 IRQ; LAPIC timer, HPET, NMI/SMI routing, SMP, physical laptop deployment, or unattended mass storage changes. IRQ storm recovery and portable ACPI routing need later qualification. Only a bounded, backed-up QEMU ISO replacement is within owner authorization.

## Acceptance and rollback
Hosted injected register-transport tests must prove exact read/write ordering, no writes on invalid topology, no unrelated unmask, correct IRQ0 mask sequencing and EOI, timer accounting and failure preservation. QEMU positive: real PIT0 ticks observed at approximately 100 Hz (test two independent samples and monotonic 100-tick interval); QEMU negative: IRQ0 route disabled but IF remains 0, software time unavailable and normal boot survives. Full QEMU 128/256/512 MiB memory, exact framebuffer, F1–F9/F10/F12 one-second overlay, keyboard/editor reflow, #UD/IST1 #DF and previous M9-3D5 cache/identity tests must pass. Owner ISO replaced only after exact commit SHA/ISO checksum, backup, and fast-forward clean checkout confirmation; otherwise leave ISO intact and provide owner-run verified installer. Revert to M9-3D5 main `3e6717c58355f408c3b97571fa5291c43d63ed61`, restoring the original ISO from backup, on any regression.

## Approval
2026-11-12: owner explicitly authorized work, merge and deployment after resolving Issue #51, and agreed to combine interactive acceptance of #48 and #51. No separate manual test of #48 required before development; automated tests remain mandatory for both.
