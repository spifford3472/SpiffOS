Date: 2026-11-14. Baseline: C2a PR #86, exact-head SHA 6431c5a9391cfeeb427869b123e254784aed28cc. C2a local full acceptance exit 0; independent GitHub Actions run #86 must be checked separately. Status: isolated hosted proof, no actual mixed-context IRQ handoff, no physical deployment.

## Why and architecture

The C2a real high-priority waiter is genuinely BLOCKED and retains its six-callee-saved-register + RET cooperative continuation. C1 and C2a separately validate authentic 20-qword IRQ0 frames for the low lock owner. A wakeup transfers the lock and marks high RUNNABLE, but neither operation can fabricate or certify the missing full IRETQ frame. The separate C2b Phase 0 helper, src/kernel/m10-d58c-c2b-resume-gate.[ch], consumes exact-generation source and destination and a trusted caller-owned per-generation context-form view. It refuses RET or invalid mode as IRQ target regardless of task READY state, plus stale generation, mismatched independently backed full saved frame, invalid IF/guard and corrupt D5.3/ledger. Both ordinary source and target must pass the prior D5.8c full frame validator; this module neither authenticates an arbitrary supplied IRQ origin, initializes a frame nor moves the CPU. It is not part of normal kernel linkage.
