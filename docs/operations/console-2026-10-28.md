## Implementation and contracts

- `console-font.c/.h`: original 5x7 glyph data for A-Z, 0-9, space, period,
  colon and question mark. Stored rows have five bits; shifting by two positions
  places the visible pixels within an 8x8 cell. The eighth row is blank.
  Other bytes, including lowercase/control/high-bit bytes, render '?', except
  newline, which is handled by the console. No full ASCII/Unicode claim.
- `text-console.c/.h`: caller-owned state borrows the Limine descriptor and
  its mappings. Fields record viewport origin, cell dimensions and logical
  row/column position. Use API functions, not manual field mutation.
- `text_console_initialize`: validates cell-count multiplication and viewport
  bounds before any screen writes, then clears the viewport and sets (0,0).
  Failure disables the state and leaves screen bytes unchanged. No allocation.
- `text_console_putc`: draws a 16x16 cell (8x8 at 2x scale), then advances the
  column. Last column wraps immediately to column zero on the next row.
  Newline resets column and increments row without drawing. Consuming the
  final cell/newline can set row equal to row count, the exhausted sentinel.
  Later input returns false with no cursor or screen changes. No scrolling.
- `text_console_write`: accepts borrowed NUL-terminated text. A full panel or
  drawing error returns false after any successfully printed prefix. An empty
  string consumes nothing. NULL input is rejected without output.
- `framebuffer_fill_rectangle` and `framebuffer_draw_cell`: the framebuffer
  module owns direct pixel stores. Validate format, pitch, address arithmetic
  and complete bounds before writing; use subtraction to avoid coordinate-sum
  overflow. Logical 0xRRGGBB colors follow reported hardware channel masks.
  Cells are opaque, so writing a space erases earlier contents in that cell.
- All operations are startup-CPU only, with interrupts disabled, no concurrent
  access, no heap, no user pointers, and no ownership transfer. Caller must keep
  borrowed metadata and mappings valid. This is not a stable kernel/user ABI.

## Boot demonstration

Keep the existing bars, border and fixed SPIFFOS title. Clear a dark-blue panel
RGB(32,32,96) at (32,112); dimensions are whole 16x16 cells with at least 32-pixel
right/bottom margins. Print lavender RGB(160,160,255) text:

```text
SPIFFOS BOOT CONSOLE
ABCDEFGHIJKLMNOPQRSTUVWXYZ
0123456789 .:?
TEXT ADVANCES THE CURSOR.
NEWLINES AND WRAPPING ARE ACTIVE.
```

At the tested 1280x800 mode, the panel has 76 columns and 41 rows. Startup
emits SPIFFOS_CONSOLE_OK only if initialization and all demo output succeeds;
otherwise CONSOLE_UNAVAILABLE, preserving prior framebuffer/text/boot markers.
Small panels may receive a partial prefix before full-panel error. There is
no visible cursor, keyboard input, BASIC READY, scrolling or interactive shell.
