## GitHub CI implementation and completed merge record

The first GitHub CI acceptance runs failed on a **test-environment
integration defect**, not a kernel regression: the disposable QEMU
test harness uses `shutil.copytree` while recursively excluding
`.git` directories, removing the metadata from Limine when cloned
inside `.local-dev/limine`. `scripts/build-image.py` correctly
refused to build without verifying the pinned Limine commit.

Resolution: the workflow now clones the official Limine repository at
exact commit `7a9013f305de0bea1f6310e76e7baba30499fef0`
to `$RUNNER_TEMP/spiffos-limine`, **outside** the SpiffOS checkout,
and symlinks `.local-dev/limine` to that pinned dependency. The
disposable test harness preserves this symlink and consequently the
dependency's Git metadata; no checksum verification was weakened.
The workflow also enables the `pull_request: edited` trigger so that
a change of stacked PR base receives new acceptance checks.
