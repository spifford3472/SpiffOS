## Implementation

`framebuffer_draw_boot_title()` in src/kernel/framebuffer.c reuses the existing
framebuffer checks and pixel packing. Seven explicit 8-byte glyphs spell SPIFFOS;
these are original hand-defined bitmaps, not a third-party font dependency.
Each byte is one 8-pixel row, with bit 7 representing the leftmost pixel.
A set bit selects white; a clear bit selects black. Each font pixel becomes a
4x4 block of screen pixels. Repeated letter data is explicit for readability.

The fixed panel is 224x32 pixels, horizontally centered at y=48, with an opaque
black background. It overlays the existing bars and leaves the purple border
intact. Require at least 256x96 pixels to retain border clearance. Unsupported
metadata or insufficient space returns false before any title writes. There
are no allocations or dynamic font loading. Descriptor and framebuffer mappings
remain borrowed from Limine; startup CPU only, interrupts disabled.

Startup draws the pattern first, then the label. A successful label emits
SPIFFOS_TEXT_OK; insufficient/unsupported title output emits
SPIFFOS_TEXT_UNAVAILABLE. Existing FRAMEBUFFER and BOOT markers remain.
Missing framebuffer metadata retains the prior serial-only startup path.
This does not implement arbitrary strings, a full character set, cursor,
scrolling, keyboard input, BASIC, user processes or console APIs.
