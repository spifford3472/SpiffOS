## Architecture and implementation
- `src/kernel/mmio-page-policy.[ch]`: pure PTE generator. Requires supervisor high-half 4KiB aligned virtual slot, nonzero aligned physical device page within CPUID physical width, empty original leaf, NX capability and enabled EFER.NXE, and **IA32_PAT index 3 explicitly verified UC**. Constructs only supervisor RW, non-executable, PWT/PCD=1, PAT bit=0; rejects any conflicting/nonzero PTE and leaves output untouched on failure. It does not touch live mappings.
- `src/kernel/x86-mmio-map.[ch]`: one boot-CPU 4/5-level transaction. Fixed **private** virtual slots `0xffffc80000000000` (LAPIC) and `0xffffc80000001000` (IOAPIC), each mapping the *firmware-discovered* physical addresses, never hard-coded hardware addresses. Validates unused CR3 root slot, acquires/zeros up to 3 (4-level) or 4 (5-level) owner-tracked RAM page-table frames, assembles all lower levels privately, then commits **one** aligned root PTE. Uses INVLPG for both virtual addresses. Destroy removes root link first, invalidates and releases exact-owned table frames; failed release poisons mapping and requires halt.
- `src/kernel/memory-boot.[ch]`: M2/M3-backed narrow page-table frame acquisition/release, ordinary FRAME_OWNER_KERNEL allocation only; no supervisor reserve. Tracks exact MMIO table physical frames and updates existing M6 retained-memory accounting; failure poisoning prevents unsafe re-use. The device register physical pages are **not** allocated from RAM and are never M2 owners.
- `src/kernel/main.c`: first validates ACPI RSDP/XSDT/MADT and xAPIC/MSR. Verifies CPUID PAT/NX/physical width, EFER.NXE, IA32_PAT index 3 UC, and a vacant, RAM-mappable CR3 root entry. Maps the two ACPI-discovered pages only through the private M2/M3 backend, then **re-walks the active CR3** with the M9-3D3 walker to confirm physical matches, 4KiB size, supervisor-only, writable, NX, PCD/PWT=1 and PAT bit clear. Emits `SPIFFOS_MMIO_MAPPED_OK` only on full proof; unsupported states retain `IF=0` and normal diagnostic boot.
- `Makefile`, `tests/mmio-page-policy-test.c`, `tests/x86-mmio-map-test.c`, `scripts/test-mmio-positive.py`, `scripts/test-mmio-negative.py`: hosted ASan/UBSan, 4/5-level, existing-root/conflicts, physical-width, NX/PAT mismatch, fault at every allocation, successful rollback, poison-on-release-failure, real QEMU positive 128/256/512 MiB, and isolated negative guest failure injection.

## Safety and unresolved next stage
**M9-3D4 proves virtual page-table mappings only; LAPIC and IOAPIC device registers were not accessed or modified, PIT0 not reprogrammed, IRQ0 not routed, and STI never enabled.** Physical APIC register access still requires an independently reviewed **memory-type alias/MTRR** validation and bounded read-only LAPIC ID/IOAPIC version tests. Only then program controller masks and redirection in a distinct IRQ0 checkpoint, with live ticks, EOI, storm/negative tests and physical fallback. This project changes no Forge Linux disk, bootloader, installed OS, local network/OPNsense, AnvilMobile, or physical laptop.
