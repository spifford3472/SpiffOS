Captures source path/function/line evidence, whole-file SHA256, candidate critical call names and explicit REVIEW_REQUIRED_NO_PREEMPTION status. Any changed tracked file, removed/added source or changed function list blocks the gate until code+new manifest are manually reviewed. The repository currently has 59 C source files and 5 assembly source files under src/kernel; the other 31 are NOT certified or tracked by this first digest gate. `--emit` prints a proposed manifest to stdout; does **not** change files. Six hosted tests prove baseline pass, changed-byte rejection, unreviewed function rejection, comment/literal masking and diagnostic-only context flags. Regex inventory is NOT a C parser: macro expansion, function pointer calls, nontrivial attributes, inline assembly and transitive callers need manual auditing. Entire nonlisted source surface remains OPEN. The diff/CI review must treat a manifest update as a deliberate security/ownership change, not a rubber stamp.

## Next implementation / rollback

D5.9-B should first design a **non-IRQ saved-IF and exact-generation exclusion contract for the allocator mutation path**. Test at each owner/counter/bitmap mutation boundary, simulated interrupts, OOM and rollback on separate fixture, then real QEMU, before instrumenting normal callers. D5.9-C/D remain separate. Don't blanket-CLI, unblock orphaned locks, free a running stack, synthesize context frames or turn on ordinary EDIT/BASIC preemption. All work on disposable Forge QEMU with `-net none` and no physical disk. Rollback: drop this feature branch; no installed files, accepted ISO, physical media, OPNsense or infrastructure changes.
