## Architecture, code paths, and why this design

Relevant sources: AGENTS.md, accepted/open decisions, system-overview, DEVELOPERS_GUIDE, ADR-m10-d53-bounded-synchronization.md, ADR-m10-d54-priority-dispatch.md, ADR-m10-d56-irq-handoff.md, ADR-m10-d57-preemption-and-priority.md, ADR-m10-d58b-frame-ownership-gate.md, ADR-m10-d58c-real-irq-lock-owner.md, ADR-m10-d58c-c2-blocked-irq-observation.md, ADR-m10-d58c-c2b-context-modes.md and ADR-m10-d58c-c2b-real-irq-bridge.md.

A distinct SPIFFOS_M10_D58C_C2B_REAL_IRQ_TEST flag selects src/kernel/m10-d58c-c2b-real-guest.c and a single call after the existing x86-irq0.S normal timer handler/EOI. This flag is never in the default kernel. The guest uses four independently mapped M2/D5.2b owned 16KiB worker stacks, plus the separate surviving permanent boot CPU stack. Exact roles: low owner, high cooperative RET-only waiter, medium independently validated IRETQ CPU worker, and reserved supervisor slot15 independently validated IRETQ CPU worker. M10-A remains the ONLY lifecycle and IRQ context handoff mutator; D5.3 remains the sole ranked lock/priority graph. The mode gate from C2b Phase 0 ensures only FULL separately verified 20-qword IRETQ destinations are considered for real IRQ handoff. It is impossible for the high RET waiter to be returned through IRETQ, even after waking, because the IRQ selector disarms BEFORE off-IRQ release.

Bootstrap starts low on a genuine cooperative stack; low acquires rank0, becomes BLOCKED awaiting an external event and physically transfers to the boot dispatcher with IF=0. Bootstrap starts high on a different physical stack; D5.3 acquire returns BLOCKED with a real reference and the waiter also physically transfers to boot under IF=0, retaining its genuine cooperative continuation. Medium and supervisor separately get initially constructed, complete 20-qword IRQ-return frames (identical layout to D5.6, not copied from RET frames), are made READY, and the low owner is woken and cooperatively resumed with high still BLOCKED. A live D5.3 donated TIME_SENSITIVE priority is verified.

The owner arms real IRQ0 switching only after checking the D5.3 graph, both destination frames and exact M10-A states. The IRQ0 stub provides the real CPU-saved source frame; the selector independently validates 20-qword source/target bounds/CS/SS/RIP/RSP/IF, actual live IF=0, D5.3 graph and D5.7 preemption guard, then uses read-only D5.7 priority donation selection and authoritative kernel_task_irq_handoff only. Medium and low consume real CPU cycles, a reserved supervisor actually completes work and the hardware-tick deadline monitor measures actual supervisor service gaps. D5.3 lock mutations, allocation/reaping, serial output and extra EOI NEVER occur in the ISR.

At >=220 real hardware ticks, after actual medium-to-donated-low priority handoffs, owner disarms selector IF=0 BEFORE releasing rank0 and waking high through D5.3/M10-A. The owner physically leaves its CPU stack via the separate tested IF-off RET switch, the dispatcher terminates unused READY IRETQ-only medium/supervisor contexts off-stack, resumes high via its original saved RET continuation, verifies high owns and releases the transferred mutex, then resumes owner's own genuine cooperative continuation for termination. Only after all exact M10-A identities terminate and no D5.3 refs remain does the surviving boot dispatcher validate stack canaries, saved RSPs and release M2 backing. Ordinary keyboard/editor then appears.

## QWEN-first provenance, errors and recovery

QWEN local qwen3-coder:30b was invoked first with a narrow initial 20-qword IRETQ frame-constructor task (43.3 seconds). Its returned frame wrote RIP/CS/flags/RSP/SS at indices 0–4 and lacked several bounds and output checks; REJECTED because actual D2 frame layout stores 15 saved GPRs first and RIP/CS/RFLAGS/RSP/SS at offsets 15–19. Coordinator used the previously accepted D5.6 constructor and wrote the separate guest, build wiring and tests. No Codex. First build had missing guarded memory-boot declarations, mixed pointer/integer conditional and missing memory-boot outer definition flag; corrected without relaxing IRQ/frame/ownership checks. After adding real guard, one unused negative-injection flag initially tripped Clang -Werror; isolated with its test-only preprocessor flags. All positive tests rerun successfully, then 15 negative tests passed. These are test-only corrections, never normal-kernel changes.

## Remaining production safety / rollback

A successful C2b four-stack diagnostic is NOT permission to turn on ordinary EDIT/BASIC process preemption. System-wide real allocator/driver/editor/keyboard/framebuffer lock and interrupt exclusion audit; production exception/owner-death orphan recovery; FPU/SIMD, per-process CR3/Ring3, SMP, calibrated hardware timing, broader fault injections and user program ABI remain OPEN. The C2b full physical test must not be merged or deployed until exact-head independent CI passes and owner separately approves a release. No automatic unlock, retransmitted IRQ EOI, custom QEMU physical drive, external network, OPNsense, or deployment changes. Rollback is to discard the isolated development branch/worktree; owner D4 ISO remains the accepted fallback.
