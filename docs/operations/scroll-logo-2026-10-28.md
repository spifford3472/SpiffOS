## Step 1: console scrolling

`row == rows` now means a pending scroll, superseding the earlier full-error
behavior. The last printed character stays visible until the next input byte
needs space. Before consuming that byte, scroll the viewport upward by one
16-pixel character row, clear the bottom row, and set the cursor to column 0
on that row. Immediate wrapping and newline semantics remain: a newline after
an exact-width wrap represents another blank line. An empty string does not
scroll. No history buffer, heap, keyboard input or visible cursor is added.

`framebuffer_scroll_rectangle()` validates all bounds first, then copies upward
top-to-bottom. Source and destination overlap; the copy direction prevents
clobbering rows still needed as input. Only viewport pixels move: neighboring
pixels and row padding are preserved. amount=0 is a valid no-op; amount=height
clears everything; larger amounts reject before writes. One-row consoles use
the clear-only case. Unsupported metadata still causes no output.

Scroll and updated cursor tests passed before logo integration. Host sanitizer
tests cover overlap, bottom clear, pending wrap/newlines, repeated output,
one-row consoles, guards/padding and invalid bounds.
