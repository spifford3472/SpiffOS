## Changes: source, drivers and integration
- `src/kernel/acpi-madt.[ch]`: track the first enabled local xAPIC ID, reject ambiguous second enabled LAPIC as unsupported SMP topology. Preserve existing single-IOAPIC and ISA timer-override restrictions.
- `src/kernel/apic-preflight.c`: require CPUID local APIC ID to match the MADT enabled CPU ID, before any hardware register access.
- `src/kernel/x86-page-walk.[ch]`: add pure tri-state read-only alias probe (PRESENT, ABSENT, UNKNOWN). Unlike supervisor-only mapping authorization, alias detection must count an existing user-accessible ancestor rather than masking a potential real alias as unknown. Tests cover absent, present, and denied table access.
- `src/kernel/apic-memory-type.[ch]`: fail-closed PAT/MTRR memory-type policy. PAT index 3 must be UC, CPUID MTRR must be supported, the default MTRR must be enabled and have a valid type, variable range count must be bounded. Both *known* HHDM aliases to the firmware APIC pages must be PROVEN ABSENT with a full readable page-table chain. Unknown or present aliases forbid reads. UC PAT entry dominates MTRR type in the x86 effective-type rules; no assertion is made about all possible undiscovered firmware aliases or physical laptop platforms.
- `src/kernel/apic-readonly.[ch]`: backend-injected pure LAPIC ID / IOAPIC ID+VERSION sanity checks. Match local APIC register ID with CPUID and MADT; match IOAPIC register ID with MADT; validate controller version, maximum redirection entry count and actual IRQ0 global system interrupt range. Wrong/missing/invalid data preserves caller output.
- `src/kernel/main.c`: after successful M9-3D4 private UC/NX page mappings and independent CR3 translation proof, inspect CPUID/MTRR MSRs and read-only HHDM alias mappings. Only when the entire safety gate passes, issue one LAPIC ID read and indirect I/O APIC ID/version reads. **IOREGSEL is written to select index 0 or 1 and restored afterwards; this modifies only the selector latch, not interrupt configuration.** No PIT0, redirection, LVT, LAPIC EOI, IRQ unmask, STI, scheduling, USB/disk/network changes. Unsupported hardware produces a diagnostic and continues with existing masked-IRQ, polled-keyboard boot.
- `Makefile`, `tests/apic-readonly-test.c`, `tests/apic-memory-type-test.c`, `tests/x86-page-walk-test.c`, `scripts/test-apic-readonly-positive.py`, `scripts/test-apic-readonly-negative.py`: add host ASan/UBSan and real QEMU positive/negative tests.

## Limits and rollback
This release is read-only in the operational sense: one I/O APIC IOREGSEL selector-latch change is needed for each indirect read and restored; **no mask, redirection, ISR/IRR, timer, or interrupt-controller configuration changes**. The controller is not enabled for interrupt delivery. Only QEMU's tested single-boot-CPU topology is verified; SMP, physical laptops, unusual ACPI/IOAPIC topologies, uninspected alternate firmware aliases, and more general MTRR combinations remain unsupported until independently validated. The known-good predecessor is M9-3D4 merge `add667982360c50410fcfbde63bd6890f9ff0384`, plus M9-3D5 docs-only merge `0f5b3143186839db55ed3c8cb278ea2e824eb35a`. Restore the saved owner ISO if staging fails; never touch a host disk or bootloader. Failures never STI/unmask hardware IRQ; all original editor and workspace behavior remains.
